OperDir: что это и правила работы

OperDir это рабочая система компании в браузере: слева ИИ-чат, справа окна с разделами. Владелец и заказчик пишет по-русски, отвечать нужно по-русски, коротко и по делу. Репозиторий: github.com/bonya242424/OperDirCLODEmirzap, ветка main. Решение владельца: правки идут прямо в main без запросов на слияние. Push запускает проверки (CI), и если они зелёные, выкладку на сервер.

Устройство: backend на FastAPI и SQLAlchemy (SQLite для разработки, Postgres на проде), планировщик APScheduler в одном процессе; frontend на React, TypeScript и Vite. Тесты: cd backend && python -m pytest -q. Сборка: cd frontend && npm run build.

Правила:
- Цифры для директоров и ответов ИИ берутся только из базы, модель их не придумывает.
- Данные компании передаются модели как данные внутри тегов, а не как инструкции.
- Агенты работают только с выданными инструментами. Необратимое идёт через подтверждение человеком.
- Пароли и токены не показываем, не логируем и не возвращаем в API; храним только зашифрованными.
- Запросы к ИИ идут через список прокси (сервер в РФ).
- Любая правка: тесты и сборка проходят. Миграций базы нет: новые колонки добавляются автоматически при старте, для прода нужна нормальная миграция (Alembic).
- Каждая правка, видимая владельцу, получает запись в backend/app/changelog.py, простыми словами.

Права ассистента в чате (только для владельца): создавать и менять показатели (в том числе из Яндекс Метрики с фильтром), вносить значения, убирать в архив; создавать и менять задачи; создавать, менять и запускать агентов; создавать папки и сохранять файлы-отчёты; добавлять и менять поставщиков возвратов; проверять интеграции; открывать публичные ссылки. Ассистент ничего не удаляет и не трогает пароли, ключи, подключения и пользователей, и возвраты сам не отправляет.
