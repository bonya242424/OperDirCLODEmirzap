# OperDir: рабочая система компании

Рабочий стол в браузере: слева ИИ-чат, справа окна с разделами. Владелец и заказчик пишет по-русски, отвечай по-русски, коротко и по делу.

## Устройство
- `backend/` FastAPI, SQLAlchemy 2, SQLite для разработки и Postgres на проде, APScheduler (один процесс).
- `frontend/` React 18, TypeScript, Vite. Окна, док, темы день и ночь через CSS-переменные в `src/styles.css`.
- `docs/` DEPLOY.md (развёртывание), UX-MAP.md (карта путей), SECTIONS.md (список разделов), DECISIONS.md (договорённости).
- Тесты: `cd backend && python -m pytest -q`. Сборка: `cd frontend && npm run build`.

## Правила
- Цифры для директоров и ответов ИИ берутся только из базы, модель их не придумывает.
- Данные компании передаются модели как данные внутри тегов (`<company_data>` и т.п.), а не как инструкции.
- Агенты работают только с выданными инструментами; необратимое идёт через подтверждение человеком.
- Пароли и токены не показываем, не логируем и не возвращаем в API.
- Запросы к ИИ идут через список прокси (сервер в РФ).
- Любая правка: тесты проходят, сборка проходит. Новые колонки в базе пока без миграций: для прода нужна миграция (см. DECISIONS.md).

## Выкладка
Push в `main` запускает CI и, если он зелёный, выкладку на сервер (`.github/workflows`). Работать через ветку и pull request, сливать в `main` после зелёной проверки.
