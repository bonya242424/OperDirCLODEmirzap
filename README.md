# OperDirCLODEmirzap

ИИ-система управления компанией: рабочий стол руководителей, показатели, задачи Битрикс24, интеграции, ИИ-чат и агенты. Полное описание: ТЗ (документ в Claude).

## Что уже работает

- Вход по email и паролю, сотрудники и роли (владелец / сотрудник), id сотрудника в Битрикс24.
- Рабочий стол: окна в стиле macOS (размер за угол), док, дневная и ночная темы, поиск Ctrl+K, чат слева, виджеты «Требует внимания», «Интеграции» и календарь.
- Интеграции: каталог из 16 источников со статусом, проверка раз в час (`INTEGRATION_CHECK_MINUTES`), время последней проверки и выгрузки. Подключения компании и сотрудников (Telegram, почта IMAP, Google Таблицы по ссылке, Яндекс Диск, FTP), секреты шифруются.
- Задачи: канбан-доска с перетаскиванием и созданием задач; задачи Битрикс24 приходят на доску только для чтения.
- Директора: показатели с порогами «внимание» и «плохо», трендом, графиком и историей значений.
- Файлы: папки, загрузка, скачивание; папку можно привязать к источнику данных (например, 1С).
- ИИ-чат со снимком данных компании (показатели, задачи, интеграции); без `ANTHROPIC_API_KEY` чат честно сообщает, что ИИ не подключён.

Что ещё не сделано: разбор файлов 1С и РНП, Метрика и Вебмастер, утренняя сводка в Telegram, агенты, бот Телемоста, календарь встреч, терминал. Клиент Битрикс24 и проверки внешних сервисов пока проверены только на подставных ответах: первый прогон на живых данных нужно сделать вместе с владельцем.

## Запуск на сервере

Подробная инструкция для разработчиков (сервер, HTTPS, автовыкладка, резервные копии): [docs/DEPLOY.md](docs/DEPLOY.md). Ниже краткая версия.

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
# заполните SECRET_KEY, POSTGRES_PASSWORD, ADMIN_EMAIL, ADMIN_PASSWORD
mkdir -p secrets
docker compose up -d --build
```

Сайт откроется на порту `HTTP_PORT` (по умолчанию 80). Войти можно под `ADMIN_EMAIL` / `ADMIN_PASSWORD`: владелец создаётся при первом запуске, если в базе нет пользователей. В `prod` система не стартует без надёжного `SECRET_KEY`.

Сайт отдаётся по HTTP. Для работы через интернет поставьте перед ним HTTPS (например, Caddy или Nginx с сертификатом), иначе пароли пойдут открытым текстом.

## Разработка локально

```bash
# бэкенд (SQLite, без Docker)
cd backend && pip install -r requirements.txt
ADMIN_EMAIL=me@example.com ADMIN_PASSWORD=change-this-pass uvicorn app.main:app --reload
python -m pytest

# фронтенд
cd frontend && npm install && npm run dev   # http://localhost:5173, /api проксируется на :8000
```

## Структура

- `backend/app` — FastAPI: `routers/` (API), `integrations/` (реестр и проверки), `llm.py` (слой модели), `scheduler.py` (часовые проверки).
- `frontend/src` — React + TypeScript: `components/Desktop.tsx` (рабочий стол), `components/apps/` (окна разделов).
- `docker-compose.yml` — база, бэкенд, фронтенд с nginx.
